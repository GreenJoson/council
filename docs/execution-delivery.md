# 执行交付与恢复

Council 将完成条件、执行证据、待处理事项和失败恢复接在现有议题与实施项上。普通讨论保持只读；只有显式委派才进入已授权的隔离执行流程。

## 完成条件

在任务卡选择执行者、审核者与写入权限后，填写验收标准并选择完成策略。批量委派使用同一策略，每项标准取自己的任务详情，没有详情时取标题。

| 策略 | 审核通过后的任务状态 | 适用方式 |
|---|---|---|
| 人工验收后完成（新委派默认） | 保持进行中，显示待人工验收 | 用户在任务状态中填写本次验收证据，再选完成 |
| Agent 审核通过即完成 | 自动完成，记录审核结论与提交 | 用户明确允许自动完成的任务 |

标准和策略在创建委派时冻结，进入实施指令、执行和复审上下文。Agent 审核通过只代表它的检查结果；人工策略要求 Human 新提交非空验收依据，不能沿用已有 Agent 摘要。Node、Rust 写入接口和 SQLite 触发器共同约束这一边界，并继续使用任务版本号拒绝过期写入。执行期间用户更新任务后，Agent 的成功与失败结果都不能覆盖这次人工更新。用户自行完成外部工作后，也可提供依据完成任务，无需重新调用 Agent。

旧委派迁移为“审核即完成”，不追改已完成状态；旧记录没有验收标准时保持空白。

## 执行记录

当前调用、历史调用和任务委派中提供“查看执行记录”，按需读取持久化的分页事件。委派保留创建条件、Agent/模型与配置修订、有效权限、执行轮次、阶段摘要、提交、审核及失败事件。恢复生成新记录，并关联旧委派，历史入口继续可查。

普通运行只记录 Runtime 已发出的生命周期和工具事件。工具参数、私有草稿和原始会话不进入审计；公开字符串先脱敏。审计行禁止覆盖，议题删除时可级联删除，因此这是本机执行证据，并非独立的防篡改存证服务。

当前原生 CLI 委派只有阶段和提交摘要，未提供的工具细节不补造。旧运行没有事件时显示明确空态。ACP 上下文占用不作为计费 Token，当前不展示推算费用；跨运行的完整工具证据检索仍属后续范围。

## 需要我处理

侧栏入口按当前项目汇总，并跳回原议题处理：待确认决策、待人工验收任务、阻断任务、最新圆桌留下的阻断分歧、执行失败，以及等待用户回复/确认的运行。

列表直接查询源状态，不另存一份可漂移的通知状态。实施项以最新委派为准，议题调用失败以最新运行为准，较新圆桌取代旧阻断终局；完成、确认或关闭后经现有同步机制更新。列表按议题合并，不提供跨项目提醒。

## 恢复与重新委派

“从已提交进度恢复”只适用于失败或取消、且已保存提交检查点的委派。恢复前检查任务版本、Agent 当前权限、受管目录、同一 Git 仓库、原 HEAD、基线祖先关系和原工作区干净状态。

检查通过后从已记录提交创建新的隔离分支、工作区和模型会话，先复审已有成果。审核要求修改时才继续执行。旧委派与旧工作区保留。恢复后的首次只读调用即使再次失败，新记录仍保留提交检查点。多个恢复请求同时到达时，只允许一个创建新的活动委派。

失败发生在提交前、但仍有受管工作区和原始基线时，可点击“接续未完成工作”。服务先验证原 HEAD 未变，再用临时索引为未提交的新增、修改、删除建立快照；原索引、文件和失败记录保留。配置、数据库、日志、备份、疑似凭据、二进制及符号链接会被拒绝，忽略文件不纳入快照。快照只带入新的隔离工作区，不生成交付提交；执行者继续补齐并测试后，才按原验收标准提交、审核和人工验收。再次中断仍可显式接续。

已保存交付提交但又有未提交改动、原 HEAD 被外部改变或原工作区不可验证时，恢复仍会拒绝。没有未提交代码时，“重新委派”从项目当前基线开始。旧任务不会因升级自动重跑或变为完成。

委派的完整 Git 检查使用 `COUNCIL_DELEGATION_GIT_MAX_OUTPUT_CHARS`（默认 1,000,000 字符），独立于只读 diff 展示预算；超过检查预算会停止，不能跳过敏感内容扫描。草稿恢复的单文件字节数也保守使用此上限。

只读的任务说明/审核调用遇到已识别的瞬时错误时，按 `COUNCIL_ORCHESTRATION_DEFAULT_MAX_ATTEMPTS` 有界重试，间隔由 `COUNCIL_DELEGATION_RETRY_DELAY_MS` 配置（默认 1500 毫秒）。写入调用、认证失败、额度耗尽、模型不可用和不明错误不自动重放。服务重启将未终结委派标为中断，用户检查后选择恢复或重新委派。

## 数据与验证

schema v15 增加完成条件，v16 增加审计、失败分类与恢复来源。Node 仍是唯一迁移者，沿用 [迁移前备份、排他事务和失败回滚](schema-migration-safety.md)；Rust 等待 sidecar 就绪后验证 v16。旧二进制不兼容 v16，回退应用时应使用对应版本的迁移前备份，不能修改版本号伪装降级。

活动委派运行期间不能修改其 Agent/Provider 配置，也不能关闭议题；请先取消并等待进程停止。

隔离测试覆盖人工验收权限/CAS、审计分页与脱敏、待办消退、迁移故障回滚、提交后脏工作区拒绝恢复、草稿保留与敏感文件拦截、并发恢复及写入不自动重放。浏览器通过真实 HTTP/SSE 与测试 Agent 替身检查交互；这不代表真实模型、安装包或生产项目已完成验收。
