# 本地发版与替换

适用于在本机从源码构建 Council，并替换 `/Applications/Council.app` 里的安装。

## 版本规则

- **每次替换本机安装都换一个新版本号。** 替换后，状态栏的 `vX.Y.Z` 就能分出新旧。提交标识和构建时间也在状态栏，鼠标悬停可看全文。
- 默认升末位，例如 0.10.1 → 0.10.2。适用于修复、界面调整，以及不改库结构的新功能。
- 以下两种情况升中位、末位归零，例如 0.10.x → 0.11.0：
  - 库结构做了破坏性升级，旧二进制读不了新库。
  - 一批大功能并入主分支。
- 版本号的正本是 `packages/desktop/src-tauri/tauri.conf.json`。Web 状态栏的版本号是构建时从它读的。另外 5 处记录由 `npm run version:set` 一次改齐，不要手改：
  - desktop `package.json`
  - desktop `package-lock.json`
  - `Cargo.toml`
  - `Cargo.lock`
  - 中英文 README 首屏
- `npm run desktop:install` 会拒绝两种构建：
  - 版本号没变的。
  - 版本号比已安装的低的。已安装的那份可能来自别的分支。

## 更新日志与审核记录

- 平时的改动写进中英文 README 更新日志的「未发布」（英文为 Unreleased）。
- 发版时把「未发布」改成 `### x.y.z — 日期`。下一批改动再新开一节「未发布」。
- 中位版本必须写 `docs/release-x.y.0.md` 发布审核记录，包括：
  - 范围
  - 自审修复
  - 源码验收
  - 替换与真实验收
  - 限制
- 末位版本在以下情况也要写审核记录，否则只记更新日志：
  - 有真实验收结果。
  - 有替换注意事项。

## 步骤

1. **确认可以发版。**
   - 改动都已提交，工作区干净。
   - 相关检查已通过：`npm run check`；改到核心链路时还要跑 `npm run test:e2e`。
2. **改版本号：**`npm run version:set -- x.y.z`。
3. **更新日志：**把「未发布」改成 `### x.y.z — 日期`。需要时补发布审核记录，并更新 README「开发与验证」里指向的审核记录。
4. **提交：**`chore(release): x.y.z …`。
5. **构建：**在这个干净提交上运行 `npm run build:desktop`。
6. **替换：**
   - 在应用里确认没有任务在执行。流水线停在等人工验收、选终稿的不算。
   - 运行 `npm run desktop:install`。
7. **收尾：**
   - 推送。
   - 如果写了审核记录，把替换与真实验收的结果补进去，单独提交。

## `desktop:install` 做什么

脚本逐项检查，任何一步不满足就中止。在真正替换之前中止，不会动现有安装。

| 步骤 | 做法 | 不满足时 |
|---|---|---|
| 新构建 | 安装包版本必须等于源码版本 | 中止，提示重新构建 |
| 干净提交 | 工作区必须干净 | 中止，提示先提交再构建 |
| 构建时间 | 构建时间不能早于 HEAD 提交 | 中止，提示重新构建 |
| 版本 | 必须比已安装的新 | 同版本时提示下一个末位版本号；更低时拒绝降级 |
| 同一构建 | 两个可执行文件的 SHA-256 与已安装的一致 | 不替换，只确保应用在运行 |
| 服务归属 | 设置里的服务地址（默认 `http://127.0.0.1:4317`）上的 Agent Service 必须属于已安装的应用 | 中止，提示先停掉开发服务器 |
| 活动任务 | `/api/v1/status` 的 `worker.activeTasks` 必须为 0 | 中止：替换会中断正在跑的委派 |
| 退出 | 先退出应用窗口，再调停止接口，让服务自己收尾 | 停止被拒（409）就重新打开应用并中止；绝不直接杀进程 |
| 备份 | 旧应用打包成 zip，放进应用支持目录的 `app-backups/`，文件名为 `Council-<旧版本>-<时间>.app.zip` | — |
| 替换 | 删除旧应用，`ditto` 复制新应用，逐字节核对可执行文件 | 中止，并给出备份位置 |
| 核对 | 启动应用，等服务就绪，核对 schema、日志库身份、议题、消息、决策、任务数量与替换前一致 | 打印警告 |

## 回退

1. 退出应用，先确认没有任务在执行。
2. 用 `app-backups/` 里对应的 zip 覆盖安装：

   ```bash
   rm -rf /Applications/Council.app
   ditto -x -k "<备份文件>.app.zip" /Applications/
   ```

库结构升过级的版本不能这样直接回退：旧二进制读不了新库，要配合迁移器留下的迁移前备份，见 [schema-migration-safety.md](schema-migration-safety.md)。

备份不会自动清理。每份 zip 有几十 MB，需要定期手动删掉旧的。
