# 架构委员会讨论协议

## 目标

让 Claude、Codex 和用户围绕同一份公开证据进行独立判断、对抗性审查和可追踪决策。共享的是结论与证据，不是隐藏推理或完整私有会话。

## 消息类型

| 类型 | 用途 |
|---|---|
| `brief` | 问题、约束、不变量、已知证据 |
| `proposal` | 独立方案、接口、权衡和验证计划 |
| `critique` | 具体反例、失败路径、安全或迁移风险 |
| `rebuttal` | 回应批评、修订方案或坚持原方案的证据 |
| `synthesis` | 共识、分歧、推荐及未决问题 |
| `note` | 简短补充或状态说明 |

## 自动讨论顺序

1. 创建议题并写清问题与约束。
2. Claude 独立提出方案，不预先看到 Codex 的倾向。
3. Codex 检查当前代码、文档或测试，对方案进行对抗性审查并写回。
4. Claude 阅读批评，逐项回应并给出修订版。
5. Codex 综合证据，明确保留分歧、风险和验证方法。
6. 用户未明确接受时，只记录 `proposed` 决策。

## 最低质量门槛

- 说明预期行为、失败条件和不可破坏的不变量。
- 至少比较一个合理替代方案。
- 每个风险指向具体机制或证据，禁止泛泛挑刺。
- 区分事实、推断和偏好。
- 结论包含验证方式、回滚条件和未决问题。

## 手动双桌面接力

在 Claude Desktop Code 中说“把当前结论发布到 Council”，再在 Codex App 中说“读取议题并审查”。Codex 写回后，回到 Claude Desktop Code 说“读取最新批评并回应”。两个客户端读取同一 SQLite 数据，不需要复制粘贴，但闲置桌面会话仍需用户主动唤醒。

## 隐私边界

发布前删除凭据、个人身份信息、私有网络信息和无关日志。只存储可公开给另一模型的内容。数据库是本地协作记录，不应提交 Git；长期有效的最终结论应由项目自己的 ADR 或架构文档承载。
